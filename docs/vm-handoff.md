# Передача ShelfWatch в Ubuntu VM

Основна копія з Git залишається на Mac у `Study/People/Пашко Максим Ігорович/2026-Fall/SP/Lab01/Work/ShelfWatch`. Порядок передачі взято зі `Study/VM-transfer.md`. Ubuntu VM та її доступність не перевірені. Не редагувати одночасно основну копію й VM-копію.

Архів `ShelfWatch-LR1-2026-10-03.tar.gz` і файл `.sha256` лежать поряд із проєктом у `Lab01/Work`. Архів містить верхню папку `ShelfWatch`, без `.git`, `firmware/build`. Git-історія залишилася лише в основній копії. SHA256 архіву читати з сусіднього файлу, не плутати з хешами firmware.

## Перед запуском

Запустити свою Ubuntu 24.04 VM до передачі файлів та підготовки демонстрації. Перевірити в її терміналі:

```sh
cat /etc/os-release
uname -sm
docker --version
docker info
```

Не називати VM перевіреною, доки ці команди й build не завершаться успішно. На цьому Mac знайдено VS Code з розширенням Wokwi; місце VS Code на комп'ютері студента треба перевірити. Симулятор може працювати на хості або у VM за наявної ліцензії. Trial не активувати. Під час демонстрації має бути відкрита саме копія ShelfWatch з її зібраними HEX/ELF.

## Передача архіву

Якщо налаштовано SSH `pliffdax@ubuntu-vm`, спочатку на Mac виконати попередній перегляд. Цей hostname та акаунт взято з прикладу передачі, їхня доступність зараз невідома. За потреби підставити реально налаштований хост.

```sh
rsync -avn --ignore-existing '/Users/pliffdax/Projects/university/Study/People/Пашко Максим Ігорович/2026-Fall/SP/Lab01/Work/ShelfWatch-LR1-2026-10-03.tar.gz' '/Users/pliffdax/Projects/university/Study/People/Пашко Максим Ігорович/2026-Fall/SP/Lab01/Work/ShelfWatch-LR1-2026-10-03.tar.gz.sha256' 'pliffdax@ubuntu-vm:/tmp/'
```

Після перегляду списку повторити з `-av` замість `-avn`. Не використовувати `--delete`. `--ignore-existing` зберігає наявні файли; якщо файл уже є, порівняти його хеш або обрати іншу вхідну папку. Альтернатива: скопіювати обидва файли через shared folder або drag-and-drop у `/tmp` VM. Не копіювати встановлені програми разом із проєктом.

У Ubuntu, де обидва файли вже лежать у `/tmp`:

```sh
cd /tmp
sha256sum -c ShelfWatch-LR1-2026-10-03.tar.gz.sha256
tar -tzf ShelfWatch-LR1-2026-10-03.tar.gz
```

Продовжувати лише за `OK` і правильного списку. Щоб не перезаписати роботу, перевірити відсутність цільової папки:

```sh
test ! -e "$HOME/study/2026-autumn/SP/Pashko/Lab01/ShelfWatch"
```

Якщо команда повернула помилку, зупинити розпакування, порівняти наявний проєкт або обрати окрему папку. Якщо папки немає:

```sh
mkdir -p "$HOME/study/2026-autumn/SP/Pashko/Lab01"
tar -xzf /tmp/ShelfWatch-LR1-2026-10-03.tar.gz -C "$HOME/study/2026-autumn/SP/Pashko/Lab01"
cd "$HOME/study/2026-autumn/SP/Pashko/Lab01/ShelfWatch"
make clean
make build
```

Архів не переносить `.git`: Git-історію показувати з основної Mac-копії. Не виконувати `git init` у VM для удаваної історії. Дві чисті збірки й збір логів виконати за [validation.md](validation.md). Порівняти два власні VM-хеші; відмінність від Mac-ELF спочатку дослідити як можливий вплив платформи, тулчейну чи debug-шляху.

## Wokwi з результатами VM

Якщо VS Code працює в Ubuntu, з кореня VM-копії виконати `code .`, F1, `Wokwi: Start Simulator`. Якщо VS Code працює на хості, спочатку передати обидва файли `firmware.elf` та `firmware.hex` до відповідної папки build саме відкритої копії. Упевнитися, що `wokwi.toml` читає цю пару, а не старі результати іншого проєкту.

За відсутності дійсної ліцензії зупинити цей етап і використати вже придбану ліцензію користувача; не натискати trial. Спостерігати ≥10 с, зберегти справжній UART-лог і скриншот із LED. Лише після цього зазначити успішну симуляцію.

## Повернення доказів

Логи VM, скриншоти та UART-лог спочатку скопіювати в окрему папку `Lab01/VM-Inbox/ShelfWatch`, використовуючи `rsync -avn`, потім `-av`, без `--delete` та без `.git`. Звірити їх з основною копією. Після перевірки перенести докази у `docs/evidence` або `docs/screenshots`, а основний звіт у `Lab01/Reports`. Копію перевіреного PDF додати до `docs` для здачі. Поточна підготовка має рівно три змістовні коміти; подальше включення доказів і PDF змінить цю історію та має відбуватися окремо перед PR.
